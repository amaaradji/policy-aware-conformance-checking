1. PROBLEMATIC TRACES - TWO CATEGORIES

A. Control-Flow Issues

  • Trace 2 has conformance < 1.00 due to the missing 'Risk Assessment' activity in the sequence.

B. Policy Violations

  • Trace 1: Activity Policy violation—'Credit Check' with 'Credit Bureau API' exceeded allowed retry count (more than 3 retries).
  • Trace 1: Resource Policy violation—'Credit Check' with 'Credit Bureau API' exceeded allowed resource usage time (over 5 minutes).
  • Trace 1: Binding Policy violation—'Credit Check' and 'Risk Assessment' activities with their respective resources had invalid activity-resource state transitions (resource unlocked or done while activity was done, and elapsed time exceeded).

2. PERFECT-CONFORMANCE BUT NON-COMPLIANT TRACES

  • Trace 1 has perfect conformance but is not fully compliant because 'Credit Check' exceeded the allowed retry count and resource usage time, and there were invalid activity-resource state transitions.

3. CORRELATION ANALYSIS

  • Policy violations can occur independently of sequence deviations, as seen in Trace 1, which followed the correct activity order but still violated multiple policies.
  • Activity Policy violations are the most common, particularly related to exceeding retry limits for retriable activities.

4. RECOMMENDATIONS

  • Update the process model to explicitly require 'Risk Assessment' before 'Approve and Disburse' to prevent missing activities.
  • Enforce strict retry counters in the implementation of 'Credit Check' to prevent exceeding the allowed number of retries.
  • Configure the 'Credit Bureau API' resource to automatically lock or reject requests that exceed the allowed usage time or retry cap, and ensure it transitions to 'Withdrawn' after 'Done'.
  • Implement validation to ensure resources are only consumed by activities in the 'Activated' state and prevent state transitions when the activity is already 'Done'.
