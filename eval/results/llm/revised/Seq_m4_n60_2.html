A. Control-Flow Issues

  • Trace 2: Contains unexpected activity 'Unexpected Activity'.
  • Trace 4: 'Checkout' occurs out of order before 'Add to Cart'.
  • Trace 6: Missing required activity 'Add to Cart'.
  • Trace 8: 'Add to Cart' is performed out of order before 'Search Products'.

B. Policy Violations

  • Trace 2: Resource policy violation—'Login to Account' (User Authentication Service): resource policy is absent.
  • Trace 4: Binding policy violation—'Add to Cart' (Shopping Cart Service): used resource 'Accounting System' instead of bound 'Shopping Cart Service'.
  • Trace 7: Binding policy violation—'Add to Cart' (Shopping Cart Service): used resource 'Accounting System' instead of bound 'Shopping Cart Service'.
  • Trace 9: Binding policy violation—'Login to Account' (User Authentication Service): used resource 'Accounting System' instead of bound 'User Authentication Service'.

2. PERFECT-CONFORMANCE BUT NON-COMPLIANT TRACES

  • Trace 1: The activity 'Search Products' used an unauthorized lifecycle transition (notactivated→failed) on 'Product Catalog Database', violating its activity policy.
  • Trace 7: The activity 'Add to Cart' used 'Accounting System' instead of the bound 'Shopping Cart Service', violating the binding policy.
  • Trace 9: The activity 'Login to Account' used 'Accounting System' instead of the bound 'User Authentication Service', violating the binding policy.

3. CORRELATION ANALYSIS

  • Policy violations and sequence deviations occur independently, as some traces have only one type of issue.
  • Binding policy violations are the most common, appearing in three different traces.
  • Some traces with perfect control-flow conformance still have policy violations, highlighting the need to address both aspects.

4. RECOMMENDATIONS

  • Model change: Update the BPMN model to enforce the correct order of 'Search Products' before 'Add to Cart' and 'Add to Cart' before 'Checkout'.
  • Activity policy fix: Ensure that 'Search Products' only transitions from 'notactivated' to 'activated' or 'failed' as authorized, and prevent direct failure transitions without activation.
  • Resource policy fix: Define and implement a resource policy for 'User Authentication Service' to control its state transitions and usage limits.
  • Binding policy fix: Enforce strict resource assignment so that activities only use their bound resources (e.g., 'Add to Cart' must use 'Shopping Cart Service', not 'Accounting System').
