1. PROBLEMATIC TRACES - TWO CATEGORIES

A. Control-Flow Issues

  • Trace 1: Missing activity 'Add to Cart'.
  • Trace 8: Missing activity 'Search Products'.

B. Policy Violations

  • Trace 2: [BINDING POLICY] - Activity 'Add to Cart' used resource 'Finance Clerk' instead of the bound 'Shopping Cart Service'.
  • Trace 5: [BINDING POLICY] - Activity 'Add to Cart' released resource 'Shopping Cart Service' (unlocked->done) while the activity was still marked as done.
  • Trace 7: [ACTIVITY POLICY] - Activity 'Add to Cart' executed without an activity policy defined for 'Shopping Cart Service'.
  • Trace 8: [ACTIVITY POLICY] - Activity 'Checkout' on resource 'Payment Gateway' performed unauthorized transitions: notactivated->unknown and unknown->activated.

2. PERFECT-CONFORMANCE BUT NON-COMPLIANT TRACES

  • Trace 2: The activity 'Add to Cart' used a resource ('Finance Clerk') that was not the bound 'Shopping Cart Service', violating the binding policy.
  • Trace 5: The activity 'Add to Cart' released the resource 'Shopping Cart Service' while the activity was still marked as done, breaching the binding policy.
  • Trace 7: The activity 'Add to Cart' was executed without an activity policy present for 'Shopping Cart Service', violating the activity policy.
  • Trace 5 and Trace 7 both followed the correct activity sequence but failed compliance due to policy violations.
  • Trace 7: No resource or binding policy violations were reported, only activity policy absence.

3. CORRELATION ANALYSIS

  • Policy violations occur independently of control-flow deviations, as some traces with perfect activity sequences still have policy breaches.
  • Binding policy violations are the most common, appearing in both Trace 2 and Trace 5.
  • Activity policy violations are also present but less frequent, with no resource policy violations observed in this dataset.

4. RECOMMENDATIONS

  • Model Change: Update the process model to enforce mandatory inclusion of 'Add to Cart' and 'Search Products' in all relevant traces.
  • Activity Policy Fix: Define and enforce explicit activity policies for all Compensatable activities, ensuring only authorized lifecycle transitions are allowed.
  • Resource Policy Fix: Review and configure resource state transitions to prevent premature release or unauthorized state changes during activity execution.
  • Binding Policy Fix: Enforce strict resource binding so that activities only use their assigned resources and ensure resource state changes align with activity states.
