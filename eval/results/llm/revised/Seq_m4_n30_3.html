1. PROBLEMATIC TRACES - TWO CATEGORIES

A. Control-Flow Issues

  • Trace 1: Missing activity 'Add to Cart'.
  • Trace 8: Missing activity 'Search Products'.

B. Policy Violations

  • Trace 2: [Binding Policy] - Activity 'Add to Cart' used resource 'Finance Clerk' instead of the bound 'Shopping Cart Service'.
  • Trace 5: [Binding Policy] - Activity 'Add to Cart' completed while resource 'Shopping Cart Service' was unlocked, violating binding state rules.
  • Trace 7: [Activity Policy] - Activity 'Add to Cart' had no activity policy defined for 'Shopping Cart Service'.
  • Trace 8: [Activity Policy] - Activity 'Checkout' with resource 'Payment Gateway' performed unauthorized transitions: 'notactivated->unknown' and 'unknown->activated'.

2. PERFECT-CONFORMANCE BUT NON-COMPLIANT TRACES

  • Trace 2: The main violation is a binding policy breach where 'Add to Cart' used an incorrect resource, despite following the correct activity sequence.
  • Trace 5: The main violation is a binding policy breach where 'Add to Cart' completed while its resource was not properly locked, even though the sequence was correct.
  • Trace 7: The main violation is an activity policy breach due to the absence of a defined activity policy for 'Add to Cart', with correct activity sequence.

3. CORRELATION ANALYSIS

  • Policy violations occur independently of sequence deviations, as several traces with perfect conformance still show policy breaches.
  • Binding policy violations are the most common, affecting multiple traces where resource assignment or state handling failed.
  • Activity policy violations are also present, particularly when lifecycle transitions are unauthorized or undefined.

4. RECOMMENDATIONS

  • Update the BPMN model to enforce mandatory inclusion of 'Add to Cart' and 'Search Products' in all traces to prevent missing activities.
  • Define and implement explicit activity policies for all Compensatable activities, ensuring only authorized lifecycle transitions are allowed.
  • Configure resource 'Shopping Cart Service' to require locking before activity completion and prevent unlocking while the activity is still running.
  • Enforce strict binding rules so that activities only use their assigned resources and ensure resource state transitions align with activity states.
